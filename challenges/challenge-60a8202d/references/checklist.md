# 逐项自检清单

交付前逐条勾选。"实际"指本次案例输入中真实存在的文件或字段，不指示例或常识。

## A. 输入与范围

- [ ] 已读取 `/input/case.json` 与 `/input/task.md`，并列出实际输入文件清单。
- [ ] 已实际打开边表、论文元数据与种子；没有按文件名或领域标签假设内容。
- [ ] 实际边记录数、论文数、种子数与报告中的数字一致。
- [ ] 损坏、空文件、无权限、无文字层材料已单独记录，没有当作"无结果"。
- [ ] 没有把"应有多少篇/多少条边"当成事实。

## B. 种子

- [ ] 种子来自 `case.json`/`task.md` 的实际字段，不是自行挑选的高被引论文。
- [ ] 种子 DOI 已规范化；只有标题时已解析到实际节点。
- [ ] 种子无引用边时已输出 `seed_not_in_edges`，而非补边。
- [ ] 种子未解析时明确说明，不拿相似标题顶替。

## C. 边与方向

- [ ] 每条边都有 `source`、`target`、合法 `direction`；非法边已丢弃并记录。
- [ ] `cites` 与 `cited_by` 的规范化方向正确，逐条可复算。
- [ ] 没有用默认方向补齐缺失方向。
- [ ] 缺少 `evidence_locator` 的边已丢弃并在 `issues.csv` 记 error `missing_evidence`，
      没有用 `row:N`/`item.key[i]` 回填。
- [ ] 缺少 `source_db`/`evidence_file` 的边保留，并在 `issues.csv` 标 warning `missing_evidence`。
- [ ] 同一对节点双向冲突已报 `reciprocal_edges`，两条都保留。
- [ ] 自分引、完全重复记录已按规则处理并记录。

## D. 图指标与路径

- [ ] 入度/出度基于唯一边计算，没有重复计同一关系。
- [ ] 弱连通分量只按实际边划分，没有把孤立种子强行并入。
- [ ] BFS 路径不超过 `--max-depth`，且是最短路径。
- [ ] 每跳都有方向、来源库、`evidence_file`、`evidence_locator`。
- [ ] 直接引用（1 跳）与间接可达（≥2 跳）已区分。
- [ ] 没有路径时输出空路径并说明，不用不同来源的边拼接。
- [ ] `--top-k` 截断已记录，没有把截断说成"没有更多"。

## E. 身份与版本

- [ ] DOI 已规范化（前缀、大小写、尾部标点）。
- [ ] 标题已做大小写/标点/空白规范化，但保留原值。
- [ ] 重复/合并候选只输出 `review_only`，没有自动合并。
- [ ] 预印本、会议版、期刊版、增补版保持独立节点。
- [ ] 同名不同文已用 DOI/年份/作者/来源拆分或并列。
- [ ] 撤稿、更正、增补已显式标注，没有静默替换。

## F. 关联文献

- [ ] 只有实际提供共被引/文献耦合/作者/数据集信号时才输出关联文献。
- [ ] 每条关联文献都有信号类型与原始定位符。
- [ ] 没有把标题相似、主题相似当作方法相关。
- [ ] 没有信号时明确写"快照内无法做关联发现"。

## G. 输出与契约

- [ ] `graph.json`、`citations.csv`、`report.md`、`result.json` 均已实际生成。
- [ ] `result.json` 逐字段覆盖 `output_contract`，键名/类型/层级未被改写。
- [ ] `case_id` 原样保留；`status` 与实际完成度一致。
- [ ] `result.json` 的节点/边/路径计数与 `graph.json` 一致。
- [ ] `citations.csv` 行数等于所有边的证据数之和。
- [ ] `report.md` 包含问题、种子、扩展与剪枝、路径、冲突、缺口、停止条件、复现步骤。
- [ ] 所有产物路径都在 `/app/work` 或 `/app/output`，没有个人绝对路径。
- [ ] 没有把 JSON Schema 描述、模板占位或预生成答案当作结果。

## H. 边界与诚实性

- [ ] 没有声称实时数据库、全球覆盖、领域穷尽或人工双人复核。
- [ ] 没有编造 DOI、标题、年份、作者、边、定位符或运行统计。
- [ ] 空结果、部分结果、失败分别说明，未完成部分清楚列出。
- [ ] 重跑同一输入得到相同结果（确定性）。
- [ ] 合成示例已明确标注"合成示例，非官方案例"。
