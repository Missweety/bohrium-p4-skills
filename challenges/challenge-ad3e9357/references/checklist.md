# 交付前逐项自检

运行前与提交 `result.json` 前逐项勾选；任何一项不满足都写入 `uncertainty` 或 `field_status`。

## 输入与契约

- [ ] 已读完整 `/input/case.json`、`/input/task.md`；存在 `environment/resources.yaml` 时已读。
- [ ] 已用 `scripts/source_index.py extract` 清点实际文件，并核对文件数、可读性与哈希。
- [ ] 已解析 `output_contract`，列出字段路径、类型、必需性；没有写死案例、号码或答案。
- [ ] 记录来自实际输入，不是示例或记忆内容。
- [ ] 已区分“实际执行的检索”和“建议但未执行的检索”。

## 检索对象与号码

- [ ] 已明确检索对象是号码、族还是主题，并记录检索起点。
- [ ] 公开号已规范为 `CC + 号码 + kind`，并与原始著录页逐项核对。
- [ ] 申请号、优先权号去分隔符规则一致，带校验位点的转换已说明。
- [ ] 解析失败保留原值并标记，未猜补号码。
- [ ] 号码、申请号、授权号未混用；优先权与申请日未混为一谈。

## 同族

- [ ] 每个族簇写明依据：显式 `family_id` / 共享优先权 / 单例。
- [ ] 同一优先权连接多个声明族时已标 `family_conflict`，未擅自合并。
- [ ] 未声称完整 DOCDB/INPADOC 同族，已说明“可观测族”边界。
- [ ] 重复记录已标 `duplicate_of`，规范记录优先官方来源。

## 主题检索

- [ ] 检索式写清关键词、IPC/CPC、申请人、引证的组合逻辑。
- [ ] 每个检索式有来源库/导出、日期、字段、过滤条件、命中数、定位。
- [ ] 区分专利文献与技术文献的检索逻辑，未混为一次检索。
- [ ] 结果只来自有授权来源，标注库名、版本与查询日期。

## 法律状态

- [ ] 状态只来自给定记录或官方登记页，未用转载页/聚合站当登记依据。
- [ ] 注明查询日期与可能滞后；未声称实时法律状态。
- [ ] 状态缺失、日期缺失/非法、无法归类、过期、冲突均已单列。
- [ ] 未把状态文本分类当作法律意见或自由实施结论。

## 权利要求与许可

- [ ] `claims.csv` 每条有版本、权利要求号、类型（独立/从属）、文本定位、来源与检索日期。
- [ ] 只描述文本实际覆盖内容，未做侵权、有效性或价值判断。
- [ ] 权利要求缺失写 `unavailable`，未推测。
- [ ] 已逐源记录许可、可展示字段、留存期限与保密要求，并给出绿/黄/红分级。
- [ ] 红色来源已降级或拒绝展示，未绕过付费墙、未上传受限数据。

## 脚本与产物

- [ ] 已运行 `patent_normalize.py`，并解释退出码 `0/2/1`。
- [ ] `normalized.csv`、`families.json`、`issues.csv` 存在于工作目录。
- [ ] `/app/output/` 下有 `normalized.csv`、`families.json`、`claims.csv`、`report.md`、`result.json`。
- [ ] `result.json` 保留原始 `case_id`，覆盖 `output_contract` 的全部字段和类型。
- [ ] 无法填写的必需字段为 `null` 且有 `field_status`/`uncertainty` 说明。

## 诚实性与边界

- [ ] 未声称实时法律状态、完整同族、等同权利要求范围或官方库全覆盖。
- [ ] 未编造专利号、申请号、优先权、状态、权利要求、来源、日期或测评分数。
- [ ] 已写明已检索范围、未覆盖来源、停止理由与人工复核建议。
- [ ] 所有路径使用 `/input`、`/app/work`、`/app/output`，不含个人绝对路径或凭据。
