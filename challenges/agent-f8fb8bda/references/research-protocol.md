# 研究协议：分解、检索规划与调用记录

本文件定义"一次深度研究怎样才算走完"。执行期只允许使用给定材料（不联网），
所有判断必须能落到 `plan.json` / `search_log.json` / `evidence_table.json` 三份记录上。

## 1. 问题分解模板

从问题原文中显式提取六类成分，缺哪类就写 `not_specified`，不要自己补：

| 成分 | 要回答什么 | 例（抽象化） |
|-|-|-|
| 对象 | 研究谁/什么系统/什么人群 | "某类材料在条件 C 下的行为" |
| 机制/因果 | 通过什么路径产生效果 | "X 是否通过 Y 影响 Z" |
| 方法 | 用什么手段测/算什么 | "不同测量方法的结果是否可比" |
| 时间/范围 | 年代、地域、尺度、纳入排除 | "材料只覆盖 2018–2024" |
| 比较关系 | 和谁比、比什么指标 | "处理组 vs 对照组的效应量" |
| 证据要求 | 什么算回答了问题 | "需要直接测量，而非仅模型推断" |

子问题写法要求：

1. **可独立检索**：能用 1–3 个检索式在材料目录里定位候选段落。
2. **可独立判无覆盖**：检索为空时能明确写"该子问题库内无材料"，而不影响其他子问题。
3. **不超过材料能回答的粒度**：材料是摘要级，就不要设"需要原始数据"的子问题；
   若研究问题本身要求原始数据，把它写成"材料不足"的证据要求子问题。
4. **依赖只写真的前置**：`depends_on` 用于"先确认术语/单位，才能比较数值"这类顺序关系；
   并行的子问题写空数组。

反例：

```
Q1 该主题的研究现状如何？          ← 不可检索、不可判无覆盖
Q2 有哪些研究方法？               ← 与 Q1 重叠，检索式相同
Q3 未来趋势？                     ← 材料为横断面研究时无法回答，应写成证据要求
```

## 2. 检索规划

每个子问题一行：

```json
{"subq":"Q2","order":2,"parallel_group":"G1","depends_on":["Q1"],
 "queries":[{"terms":["term A","term A 同义写法"],"scope":"materials/","rationale":"术语来源：材料标题与摘要实际用词"}],
 "shared_query":null,
 "stop_condition":"命中段落已覆盖全部包含该术语的文件，或连续 2 个检索式无新增相关段落"}
```

规则：

1. 检索式用**材料里的实际词形**（先看 `corpus.txt` 的高频词），不要用模型偏好的术语替换原文说法。
2. 同义词、缩写、单位变体（`mg/L` vs `mg L-1`）、旧称各查一次，并在 `search_log.json` 分别记录。
3. 共享检索只做一次：写 `shared_query: "S1"`，在 `search_plan.json` 的 `shared` 段定义 S1 的检索式与结果引用。
4. 停止条件必须可判定（命中饱和 / 覆盖所有含该词文件 / 触达预算），不能写"查到足够为止"。
5. 检索顺序：先术语与范围（Q 依赖链的根），再比较与机制；依赖未完成的子问题不得先写结论。

## 3. 工具调用记录

每个动作一行，包含参数与返回摘要：

```json
{"step":7,"subq":"Q2","tool":"grep -rn","args":"-- \"removal efficiency\" materials/",
 "hits":[{"path":"materials/a.md","line":120},{"path":"materials/b.md","line":44}],
 "empty":false,"decision":"a.md 上下文相关，b.md 仅出现在参考文献，未采用"}
```

- 失败也要记：`{"tool":"grep","error":"binary file matches","decision":"改用 python 逐行读取"}`。
- 记录 `decision` 是"为什么采用/不采用"，没有它，证据表就无法复核。
- 同一检索式重复执行时写 `repeat_of`，说明为什么重跑（如材料更新）。

## 4. 证据抽取

每条证据只回答一个子问题的一个判断：

1. `claim` 是可判断真假的陈述句，不是主题词。
2. `quote` 逐字复制，包含能独立读懂的最小上下文；跨句引用用同一段内连续文字，不拼接。
3. `locator` 给文件内行号区间；PDF 用 `p.N ¶k`，并在 `limits` 说明是 PDF 页序。
4. `source_type` 依据材料中可见信息：有期刊名/卷期页/DOI 才可标 `peer_reviewed`；
   标注 "preprint/bioRxiv/arXiv" 标 `preprint`；综述文章标 `review`；机构报告标 `report`。
5. `stance` 取 `support` / `refute` / `mixed`，按该证据相对该子问题主张的方向判定；
   同一材料对不同子问题可以有不同 stance。

反例：把一句"X 可能影响 Y"抽成"X 导致 Y"；把讨论段的推测抽成结果；把参考文献列表里的标题当证据。

## 5. 综合与写作顺序

1. 先写证据矩阵（机器可读），再写正文；正文每句从矩阵里挑证据，不从记忆里挑。
2. 每条结论句末尾挂证据 id；同一句最多两个 id，且两个 id 必须都直接支撑该句。
3. 冲突证据在正文单列小节，先陈述双方，再写"差异可能来自…（只有材料写明原因才可归因）"。
4. 研究空白只能从 `gaps` 生成：`{subq, basis: not_covered|empty_query, missing}`。
5. 待验证清单写"要什么证据才能把当前结论从 B 级升到 A 级"，不写"建议进一步研究"。
