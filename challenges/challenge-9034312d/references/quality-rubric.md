# 质量评分表（装置图/技术路线图）

对齐题面的评分维度，把“画得对不对”落成可勾选的检查项。每项 0/1/2：0=缺失或错误，1=可接受但需人工修补，
2=可直接交付。

## 1. 实际效果（40 分）

| 检查项 | 对应证据 | 2 分标准 |
|-|-|-|
| 部件正确 | `route_graph.json#parts`、`element_map.json` | 名称与数量与材料一致；同类部件（如两个阀）可区分；类型形状与语义相符 |
| 连接正确 | `connections[].from/to/kind` | 接口对应；物料/气体/信号/废液不混用线型；无凭空补管、无断头箭头 |
| 顺序正确 | `stages[].order/depends_on` | 阶段编号与正文一致；依赖只指向更早阶段；主序列、并行、回流可读 |
| 阶段完整 | `stages[].objective/outputs/milestone` | 每个阶段有可验收目标与产出；材料声明了里程碑时要画菱形，未声明则告警并写入 uncertainty |
| 数据编码 | `units`、`legend` | 温度/压力/流量等标注有单位与来源；图例与线型一一对应 |
| 可核验 | `selfcheck.json`、`exports.json` | `route_check.py` PASS；每条元素有 `source`；导出参数登记 |
| 可编辑 | `route.svg` 图层、`spec.json` | 文字为 `<text>`；改标签只改 spec 重建 |

常见扣分：管路被“补全”；废液箭头方向反了；阶段与正文步骤错位；图例颜色与实际不符；只交截图。

## 2. 使用增益（25 分）

| 检查项 | 2 分标准 |
|-|-|
| 质量增益 | 相比“把部件名排成一排”的画法，有装置区/路线区分区、类型形状、流向语义、阶段里程碑 |
| 效率增益 | 一次 `extract → build → check` 得到可交付初稿；改图只改一处 |
| 可验证性 | 同一 `case.json` 重跑版式一致（网格布局由脚本计算，无手工拖拽） |

## 3. 创新增益（15 分）

| 检查项 | 2 分标准 |
|-|-|
| 结构化映射 | 装置清单/工艺段落 → `parts/connections/stages` 中间表示，可读可改 |
| 流向语义 | 物料、气体、能量、信号、废液用可区分线型；方向显式，推断项虚线 |
| 布局约束 | 蛇形网格 + 阶段卡四行结构 + 依赖箭线 + 图例避让，长文本自动换行/截断 |
| 自动校验 | 画布/面板越界、重叠、阶段顺序、里程碑、证据、配色、element_map 均机检 |

## 4. 可靠体验（10 分）

| 检查项 | 2 分标准 |
|-|-|
| 调用正确 | 触发词、输入路径、命令与 SKILL.md 完全一致 |
| 稳定性 | 缺 matplotlib 时 exit 0 且保留 SVG；部件数量 5–20、阶段 2–6 均能稳定排版 |
| 异常处置 | 缺参数/接口冲突/阶段目标过长都有明确降级并写入 `uncertainty` |

## 5. 交付前清单

- [ ] `route_check.py` 输出 PASS，`selfcheck.json` 中 `errors=[]`
- [ ] `element_map.json` 覆盖部件、连线、阶段、图例、注释，`source` 非空
- [ ] 每类图元抽查 ≥2 条能回到原文（尤其回流/废液支路方向）
- [ ] 阶段 order 连续、依赖不明显倒挂；有里程碑时菱形可见，无声明时不虚构
- [ ] `units` 与 `scale_bar` 存在；非等比图写“示意/not to scale”
- [ ] 长标签已换行或缩字号，未越出部件/阶段框，且不截断实体名
- [ ] `result.json` 的 `status` 与 `limits/uncertainty` 如实反映降级情况
- [ ] 包内不含令牌、不含个人绝对路径、无二进制或软链接
