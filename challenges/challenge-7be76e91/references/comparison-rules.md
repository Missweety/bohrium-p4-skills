# 比较口径与评分规则

## 1. 七类字段（每方案都要填）

| 字段 | 抽取线索 | 缺失时 |
|-|-|-|
| 目标/假设 | 目标、目的、研究问题、假设、hypothesis | 记 `missing_fields`，目标维度降分 |
| 变量 | 自变量、因变量、变量、factor | 不参与变量一致性检查 |
| 对照 | 对照、空白、阴性、阳性、sham | 在 `risks` 标"缺对照" |
| 步骤 | 步骤、流程、protocol、第1步 | 工期只能取总工期 |
| 参数 | 参数、条件、`参数=值 单位` | 无法做参数越界门控 |
| 资源 | 设备、仪器、耗材、试剂、人员 | 无法做资源不可得门控 |
| 判读标准 | 判读、判定、指标、终点、criterion | 在 `confirmations` 要求补齐 |

## 2. 硬门控（先淘汰，再打分）

```
资源不可得：case.json available=false/停机/已满，或材料含 停机/已满/缺货/未到货/无法预约
            且资源名出现在该方案文本；方案自身风险叙述里的"已满"不算全局合同
超预算    ：成本（已知项之和，且无缺价）> 预算，且币种一致
参数越界  ：方案参数与 case.json 有限参数域按参数名比较；无域时回退材料 同名 ≤/max 上限
超窗口    ：方案总工期 > 窗口/截止
```

参数域匹配优先"参数名相同/包含"，其次同单位文本上限；单位不同不硬判，写入 `uncertainty`。

## 3. 评分与归一

默认权重（显式、可改）：目标 0.20 / 可行性 0.25 / 成本 0.15 / 时间 0.15 / 风险 0.15 / 证据 0.10。

```
可行度 = 0（有门控）| 2（成本完全无可解析数据）| 3（有缺价/未定域）| 5（全部核实）
成本分 = 仅幸存者内位次：最低 5 → 最高 2（至少 2 个可比才有分）
时间分 = 仅幸存者内，同上
风险分 = max(0, 5 - 2×未缓解风险条数)；无风险条目 → null
证据分 = min(5, 1 + 带来源条数)；来源可为文件行号或 case.json 路径
加权分 = Σ(权重×得分) / Σ(可用权重)
```

`null` 不是 0：该维度整列剔除并缩小分母，同时写入 `uncertainty`。
被淘汰方案不参与成本/时间位次——否则"已被淘汰的便宜方案"会拉低幸存者的相对分。

## 4. 成本与工期

```
成本 = Σ(数量 × 对应品名单价)；按品名匹配，品名不匹配不套用其他耗材单价
      结构化 cost 可为数字 / {amount,currency} / [{item,qty,unit_price}]
工期 = 材料给出"总工期/总时长"则取之；否则 Σ(分步天数)；周 → ÷7
```

缺价项不计入、结果标"下限"；全部缺价时成本为 `null`（不写 0，避免"免费"误读）。
结构化数字成本未写币种时，用预算/报价中的唯一币种兜底；币种仍不一致 → 成本位次 `null`。

## 5. 选择、舍弃与敏感性

- 选择：通过门控者中加权分最高。
- 舍弃理由：硬约束明细（门控 + 资源名）或与最高分的差值。
- 敏感性：给出次优反超所需条件；两方案打平时要求补一条判别性证据。
- 全部淘汰：`no_feasible_plan`，给放宽建议，不硬选。

## 6. 复跑

同一材料版本、同一权重、同一命令应得到相同排名。`run_case.py` 自动连跑两次，
把 `run1/run2` 草稿与矩阵哈希写入 `determinism`；不一致时 `validation` 标 FAIL，
并需核对输入 sha1（`input_versions`）与材料版本。
