# 质量检查表（对齐 5 个评分维度）

评测按「实际效果 40 / 使用增益 25 / 创新增益 15 / 可靠体验 10 / 生态贡献 10」计分。
本表把每个维度翻译成本包可执行、可复查的检查项；`scripts/deck_plan.py` 覆盖第 1 组的机器检查。

## 1. 实际效果（40 分）

| 检查项 | 合格线 | 谁来查 |
|-|-|-|
| 报告目标与受众 | `audience` 写明听众身份与先验知识；页数、时长、结论强度随受众调整 | 人工 + `outline` |
| 主线完整 | `problem / approach / results / conclusion` 四槽非空，`limitations` 建议非空 | `deck_plan check` |
| 一页一主张 | 标题是判断句，不是“实验结果”“方法介绍” | 人工 |
| 信息密度 | ≤6 条要点、每条 ≤14 字、单页总字数不过载 | `deck_plan check`（硬错误） |
| 时长匹配 | 每页 30–60 秒；总秒数与目标时长差 ≤ max(30 秒, 10%) | `deck_plan check`（硬错误） |
| 证据可溯 | 图表编号、数字、引文能在 `corpus.txt` 命中 | `deck_plan check` + `quote_check.py` |
| 讲稿可用 | 每页 `notes.say` ≥20 字、30–60 秒可讲完，不复述页面 | `deck_plan check` |
| 时间分配表 | 分段（开场/问题/方法/结果/结论）汇总与总时长一致 | `timing.md` / `timing.csv` |

## 2. 使用增益（25 分）

- 相同论文、相同受众与时长下，基础 Agent 常见失败是“按段落切页、页数与时长脱节”；
  本包用页预算 + 秒预算 + 密度硬线把这两类返工前置到生成阶段。
- 效率增益可量化：`deck_plan check` 一次运行报出全部超字数/超时页面，人工返工从“通读全稿”
  变成“按错误清单定点修改”。
- 可验证性：同一 `deck_spec.json` 重复运行输出稳定（纯函数式渲染，无随机数、无网络）。

## 3. 创新增益（15 分）

- 秒级页预算：把“时长”拆成每页 30–60 秒并做总量守恒检查，而不是只给页数上限。
- 讲稿与页面分离：`speaker_notes.md` 按“讲稿/过渡/预设问答”三段生成，且检测“口播复述要点”。
- 结构化规格：`deck_spec.json` 可被其他工具复用（生成 pptx、套模板、做 diff），不是一次性文本。

## 4. 可靠体验（10 分）

| 情况 | 处置 |
|-|-|
| 未声明时长 | 仍出稿，按逐页秒数反推总时长并写 warning |
| 未声明受众 | 硬错误：受众决定背景比例，不能默认 |
| 论文/材料不可读 | 只用已读部分，`status: partial` + `limits`，不虚构图表 |
| 图表编号在原文不存在 | 硬错误，必须改编号或删页 |
| 无 python-pptx | 交付 `deck_spec.json` + `deck.md` + `speaker_notes.md`，`status: partial`，不报错 |
| 页面超字数/超时 | 一次性列全，按错误清单拆页或删次要内容 |

## 5. 生态贡献（10 分）

- `SKILL.md`：触发条件、输入别名、执行流程、输出契约、自查、降级六段齐全。
- `references/`：默认契约、本检查表、合成示例（非答案），可被其他幻灯片包复用。
- `scripts/`：仅标准库，`spec_io.py` 的 Markdown 渲染与可选 pptx 构建可独立复用。
