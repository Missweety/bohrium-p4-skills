# 逐项自检清单

交付前逐条勾选。"实际"指本次案例输入中真实存在的文件、记录或状态。

## A. 库与查询

- [ ] 已读取 `/input/case.json` 与 `/input/task.md`，列出实际请求的库集合。
- [ ] 逐库记录了查询式、字段能力、分页/额度与实际结果数量。
- [ ] 没有把同一查询机械复制到所有库；未联网时明确写"快照/导出"。
- [ ] 库的失败、限流、无权限、空结果分别记录，未混为一种情况。
- [ ] 没有声称实时检索或全局覆盖。

## B. 记录与字段映射

- [ ] 已打开实际响应/导出文件，没有只按 `case.json` 标签假设内容。
- [ ] 每条记录都能回溯到 `source_db` + `raw_file` + `raw_locator`。
- [ ] DOI 已去前缀、转小写、去尾部标点；非法 DOI 未用于聚类。
- [ ] PMID 为纯数字；非法值未当作有效标识符。
- [ ] 标题规范化保留原值，仅用于匹配。
- [ ] 作者、年份、期刊、类型已规范化；未识别值保留原串并记录。
- [ ] `missing`（库未提供）与 `unknown`（库明确写未知）已分开。
- [ ] 没有用其他库的值填补某库缺失字段。

## C. 去重

- [ ] 先按 DOI、PMID 精确聚类；同组记录确实共享规范化标识符。
- [ ] 模糊候选同时满足 Jaccard ≥ 阈值（默认 0.9）与年份差 ≤ 容差（默认 1）。
- [ ] 模糊默认只出候选，未自动合并；如使用 `--fuzzy-merge` 已记录理由。
- [ ] 年份缺失或超出容差的近失项已列出，未强行合并。
- [ ] 同名不同文、预印本/期刊版未因标题相似被误合并。
- [ ] 重复组与候选行的 `decision` 与实际操作一致。

## D. 合并与冲突

- [ ] 字段值按 priority 最小者选取；并列规则可复现。
- [ ] 每个被选字段都有来源库、文件、定位符与记录号。
- [ ] 所有规范化值不一致的字段都进入 `conflicts.csv`。
- [ ] 冲突中被选值与其余值都保留，未静默丢弃。
- [ ] 作者顺序差异如实列为冲突，未擅自认定相同。
- [ ] 合并结果重跑一致。

## E. 回溯与计数

- [ ] `provenance.csv` 覆盖每个簇的每个 present 字段与每个来源值。
- [ ] 每个字段恰有一行 `selected=yes`（或明确说明多来源同值的情况）。
- [ ] 至少给出一个完整链路示例：
      库 → 查询 → 原始响应定位 → 映射 → 去重簇 → 合并值。
- [ ] `records_valid + records_dropped = record_rows_read`；无身份行计入 dropped 并退出 2。
- [ ] `merged.json`、CSV、`report.md`、`result.json` 的计数一致。
- [ ] 单库独有记录与字段能被识别，不只报告合并后总数。

## F. 失败与缺口

- [ ] 每个失败/缺失库都在 `gaps` 与报告中出现，含状态与影响。
- [ ] 空结果库与未查询库已区分。
- [ ] 坏 JSON/CSV、编码异常、无身份行已逐条记录，其他文件继续处理。
- [ ] 部分结果明确标注未完成部分，没有把 partial 写成 ok。
- [ ] 未用其他库记录补造失败库的结果。

## G. 输出与契约

- [ ] `merged.json`、`provenance.csv`、`conflicts.csv`、`duplicates.csv`、
      `report.md`、`result.json` 均已生成。
- [ ] `result.json` 逐字段覆盖 `output_contract`，键名/类型/层级未被改写。
- [ ] `case_id` 原样保留；`status` 与实际一致。
- [ ] 所有路径在 `/input`、`/app/work`、`/app/output` 下，无个人绝对路径。
- [ ] 没有把 Schema 描述、模板或预生成答案当作结果。
- [ ] 合成示例已标注"合成示例，非官方案例"。

## H. 诚实性

- [ ] 没有编造记录、标识符、字段值、查询、响应、状态或统计。
- [ ] 推断处标注"推断"并给出依据。
- [ ] 已知限制（标题匹配、作者切分、缩写、快照边界）已在报告中说明。
