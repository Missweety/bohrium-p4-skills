# Evidence-bound academic compliance review

Read the real `/input/case.json`, `/input/task.md`, all manuscript pages, supplementary files, cited material, applicable policies, author guidelines, licences and resource listing `environment/resources.yaml`. Determine what the workorder actually requests; the input's `output_contract` and case_id control delivery. Work under `/app/work` and place results under `/app/output`. Never substitute a fabricated article, rule, journal policy, ethics approval or formal legal/ethics opinion.

1. Build a source inventory including version, date, access limitations, full manuscript page/section coverage and supplied policy scope. `python scripts/evidence.py extract --input /input --out /app/work/evidence.json` extracts source text per PDF page, DOCX paragraph and text line, with hashes; inspect its CLI help for supported file types. It does not read images or prove complete scientific understanding. Open actual figures/tables, pages and material it cannot extract; use available OCR/visual rendering for scans. Track unreadable pages separately. Read long papers in batches and preserve a ledger of all sections checked. A failed extraction or inaccessible reference means that aspect is unverified.
2. Build an applicability matrix for the case. For integrity, citations, privacy/restricted data, third-party rights/licences, human/animal research and submission instructions, record `checked`, `not_applicable` with reason, `unverified`, or `not_checked`. Include each topic required by the workorder. For each applicable requirement identify the actual rule text, issuing body, title, edition/effective date, clause, scope, manuscript location, and evidence of compliance or potential gap. Verify which requirements govern this manuscript and date; don't invent policies or treat a general guideline as binding. A manuscript may refer to supporting documents elsewhere—inspect them before declaring a statement absent. A search hit or absence from an incomplete extract is only a candidate, not a verdict.
3. Audit references and claims using supplied original sources: identity/DOI/title/year/authors where accessible, quotation/context and whether the citation supports the specific assertion. Missing access is `unverified`, not false. For data, ethics and privacy verify relevant populations, permissions, approval/waiver and consent statements against supplied material; a missing statement alone is not proof of absent approval. Do not reproduce unnecessary personal identifiers; quote the minimum needed, with redaction and locator. For images, code, data and tables, check source, licence, permitted use, attribution and actual scope; lacking licence information is unknown, not proof of infringement. Disclosure, contribution or publication-overlap concerns are leads requiring documents and independent review, not accusations of misconduct. Check venue instructions only when the actual applicable version is available.
4. Cross-check each candidate against the strongest counter-evidence, exceptions and evidence elsewhere. A supported finding requires a specific manuscript excerpt or documented complete-scope absence AND actual governing rule/requirement or explicit contradictory evidence. Distinguish `confirmed_error`, `insufficient_evidence`, `needs_verification`, `editorial_suggestion`; evidence-limited scope cannot support an absence claim. Severity is impact-based (`high` central risk, `medium` material gap, `low` local; `unverified` for unresolved premise), with reasoning. For each finding include exact file and page/paragraph/line, source quote or explicit absence search scope, actual rule/source locator and version, rationale, impact, precise corrective action, and who must confirm it. Cite and explain successful compliant checks too; zero findings is allowed if evidence warrants it. Do not identify the author as dishonest or adjudicate misconduct.
5. Write actual `/app/output/review.md` and `/app/output/review.json`: coverage; applicability/check matrix; prioritized findings with claim and rule evidence; verification state, severity, corrections; unverified items; source versions and limitations. Extract helper is reusable for exact locators: its verifier accepts findings with `claim_quote`, `claim_location`, `evidence_quote`, `evidence_location`, where locations contain file and page/paragraph/line. `python scripts/evidence.py verify --index /app/work/evidence.json --review /app/output/review.json --out /app/work/quote-check.json` checks exact literal occurrences in hashed indexed sources, not applicability or correctness. For legitimate absence, redacted identifiers or image-only evidence don't invent a quote merely to satisfy this helper: record reason and alternative inspection; automatic literal check is not applicable. A nonzero verifier exit means this run failed; never use an earlier quote-check even if still present. Check actual policy text and manuscript meaning independently.
6. Write `/app/output/result.json` with every actual output_contract field and type, preserving case_id and reporting status and uncertainty honestly. Supply paths and actual findings, not schema descriptors, boilerplate or only a plan. Separate missing materials from a substantive negative result; mark partial if required review cannot be completed. Validate referenced paths and result semantics against the current case. [references/output-contract.md](references/output-contract.md) states helper boundaries; use [references/checklist.md](references/checklist.md) for adversarial checks. Save usable partial results early under the 900-second budget.

Example (synthetic, not an official case): a paper says participant consent was obtained; a supplied guideline explicitly requires a consent statement. If both are readable and applicable, record a compliant check with both locators; if the guideline is absent mark its applicability unverified rather than assert a breach. PDF text extraction needs `pdftotext` (Poppler); text/DOCX operations use Python 3.10+ standard library. No network is required for supplied evidence; if external lookup is permitted, verify against primary official sources and record retrieved version/date, without claiming access that failed.
