# 方法说明：修订锚定、引用同步与版本管理

## 1. 为什么不用"整段重写"

学术写作里，"改得准"与"改得可追溯"是一体的：整段重写无法回答"改了哪一句、依据是什么、
能否只接受其中一处"。本 Skill 因此只做**定点修订**：

- 每条指令必须先落到**逐字锚点**（要在原稿该段能找到，找不到就记 `skipped`）；
- 修订在 OOXML 层表示成 `w:del` + `w:ins`，Word「审阅」可逐条接受/拒绝；
- 不改段落结构、不重建表格、不重排页眉页脚。

## 2. 修订锚定（为什么不会被已有修订污染）

段落的可见文本由若干 run 拼成。本 Skill 做替换时：

1. 只在段落的**直接 `w:r` 子元素**里按"连续 run 组"查找锚点；
2. `w:ins` / `w:del` 是独立的兄弟元素，其内部 run 不属于"直接子元素"，**不会被命中**；
3. 命中后把目标 run 拆成四段：`前段(w:r)`、`<w:del>旧</w:del>`、`<w:ins>新</w:ins>`、`后段(w:r)`；
4. 每条修订分配唯一 `w:id`，`w:author` 与 `w:date` 固定，便于审阅面板追溯。

因此：

- 已有修订的段落可以继续修改，新标记与原标记互不覆盖（实测：在已含 18 个标记的稿件上再改，标记数
  变为 20，`w:id` 仍全局唯一）；
- 如果锚点跨了超链接/复杂域等非直接 run 结构，脚本**不做安全假设**，记 `skipped` 并说明原因。

## 3. 引用同步算法

1. 抽取正文引用 `[n]`、`[n,m]`、`[n-m]`（按出现顺序），以及参考文献表条目 `[n] ...`；
2. 用"正文首次出现顺序"生成 `old → new`；只出现在参考文献表、正文未引用的条目排在最后；
3. 正文引用用修订标记改写为 `new`（连续编号折叠成区间，如 `[1-3]`）；
4. 参考文献条目前导编号同步改写，并按 `new` 升序重排条目；
5. `citation_map` 记录 `old/new/首现段落`，供人工核对。

不改文献著录内容（作者、题名、年份、出版社），只改编号与顺序。

## 4. 版本谱系与回退

| 版本 | 文件 | 角色 |
|-|-|-|
| v0 | `original.docx` | 原稿只读副本；sha256 记录在 `versions.json` |
| v1 | `revision.docx` | 含修订标记的修订稿 |
| v1-clean | `clean.docx` | 全部接受修订后的干净稿 |

- 原稿与各版本在同一输出目录，可直接 pairwise diff（`revision.diff` 给出 v0→clean 的逐行差异）；
- 回退方式写死在 `versions.json.rollback`：把 v1 换回 v0 即回到原稿；
- 任何一步失败都仍写出已生成的版本与失败原因，不删除原稿。

## 5. 导出与预览

- `clean.docx` 由 `accept_all()` 生成：删除所有 `w:del`（含 `w:delText`）、解包所有 `w:ins`、
  移除 `*Change` 元素，保证不残留修订；
- 预览优先 `soffice --headless --convert-to pdf`（隔离 `HOME` 与 `UserInstallation`，超时 180s），
  校验文件以 `%PDF` 开头且能数到 `/Type /Page`；
- 无渲染器或转换失败时写 `preview.html`（逐段 + 行号），并在 `limits` 如实说明，绝不伪造 PDF。

## 6. 诚实边界

- **语义改写需要模型判断**：如"更有感染力""论证更有力"，脚本不猜，进 `pending_instructions`；
- `self_check` 只能证明"修订真实存在、可接受、可复核"，不能证明改写符合学术意图；
- 不得把 `partial` 当失败丢弃：它意味着"已交付可用稿 + 明确列出未完成项"。
