# Source-bound manuscript argument review

Read `/input/case.json`, `/input/task.md`, every actual manuscript and supplied reference/data, plus `environment/resources.yaml`. The workorder and actual `output_contract` determine scope and field types. Work in `/app/work`; put a complete, source-derived report and `result.json` in `/app/output`. Inspect files themselves, not their labels. Do not submit prewritten findings or claim a hidden-case result.

1. Identify primary manuscript, version, supplement, cited full-text documents and figure/table sources. Inventory/extract: `python scripts/evidence.py extract --input /input --out /app/work/evidence.json`. For each PDF page use `pdftotext -layout` if installed; for scanned/missing pages use available OCR or visual page rendering and mark what was actually read. For DOCX the helper extracts paragraph text; open drawings/tables separately when needed. Do not treat file hashes or extraction as semantic reading. Review all actual pages and sections, tracking total/covered/unreadable pages. For long documents use batches and carry forward structured claims; never claim full review after truncation. Inspect actual tables/figures and references when relevant; distinguish inaccessible cited work from contradictory evidence.
2. Build a claim-evidence ledger in `/app/work/claims.json`: each important claim records verbatim quotation, actual file and page/paragraph locator, section, speaker (`author`, `cited_author`, `hypothesis`, `control`, `limitation`), modality, population/intervention/time, associated methods/results and their locators. Build from abstract and introduction through methods, results, discussion, conclusion, tables and supplied sources. Identify each introduction promise and its corresponding method/result; mark unassessed if missing or unreadable. Separate primary analysis, exploratory and hypothetical analyses. Do not conflate patient groups, time points, association with causation, unadjusted and adjusted results, or quotations with author endorsements.
3. For each candidate concern compare the original claim with the strongest *available* supporting and contrary evidence; explicitly test alternative explanations: pre-specified control, stated assumption, cited author's position, subgroup/context, denominator, direction, limitations, statistical uncertainty, and an explicit qualifier elsewhere. If a cited primary text is unavailable, mark citation support `unverified`, not false. Distinguish `confirmed_error` (specific conflicting evidence), `insufficient_support`, `needs_verification`, and `editorial_suggestion`. A lack of observed evidence after incomplete access is not proof of absence. Check six facets when relevant: facts, citation support, methods, statistical reporting, argument chain and academic standards; do not claim statistical recalculation or misconduct determination without actual evidence. Track each facet as checked, no finding, not applicable or unverified.
4. Prioritize by effect on central result and repairability: `high` undermines a central conclusion or key evidence; `medium` materially affects a secondary inference/reproducibility; `low` local or clarifying; `unverified` for uncertain premise. Each issue needs an exact manuscript excerpt and independent evidence location, reasoned warrant, impact and precise proposed sentence or experiment/analysis that would close the gap. Say what the existing data can support; do not invent a statistic or citation. If no actual issue is established, report that honestly. Sort by importance and keep a separate unresolved list.
5. Write `review.json` with `case_id`, `status`, `coverage`, `claims`, `findings`, `facet_status`, `unverified`, `sources` and `uncertainty`; write a human-readable `/app/output/review.md` containing prioritized findings, exact excerpts and concrete revisions, plus coverage and limitations. Each finding has `id`, `type`, `severity`, `claim_quote`, `claim_location` (file + `page` for PDFs or `paragraph` for DOCX / `line` for text), `evidence_quote`, `evidence_location`, `reason`, `unverified_reason` (when applicable), `revision`, and `verification_state`. Supporting and conflicting quotes must be literal. Run `python scripts/evidence.py verify --index /app/work/evidence.json --review /app/output/review.json --out /app/work/quote-check.json` and fix every failure. A finding whose source or locator is genuinely unavailable keeps `verification_state` as `unverified`/`needs_verification`/`pending_verification`/`待复核` with a non-empty `unverified_reason` (or `reason`); the helper then records `accepted_unverified` instead of failing only when the quote is absent or the located page has no extractable text (visual verification route). A supplied quote whose file is not indexed, whose locator lacks a unit, or that is absent from a text-bearing unit still fails. Any other nonzero verify exit means this run failed: do not use a previous quote-check file as current evidence, even if it still exists (for example, an unreadable index prevents safely determining the input boundary). A passing run with accepted-unverified items reports `status: ok_with_unverified`, not a clean `ok`. The helper checks literal presence at locator, not scientific reasoning. For OCR or images verify visually and record that route; don't claim automatic quote verification.
6. Write `/app/output/result.json` with every original output_contract field and original case_id, matching required types. Map actual report/claims/findings and artifact paths to the case's actual fields, not JSON Schema descriptors. Preserve status and uncertainty; an inaccessible source or unreviewed section makes the relevant facet unverified and may require partial. Check all paths and field meanings; the provided helper does not validate arbitrary contract schemas. Give actual results, not only a plan.

See [references/review-checklist.md](references/review-checklist.md) for independent adversarial checks and a synthetic example. Python 3.10+, standard library and optional `pdftotext`; no network required. If input parsing fails, produce a partial result with explicit unreadable paths; never silently substitute guessed facts. Full citation-text checks require access to the cited source; background knowledge alone does not establish what a paper says.
